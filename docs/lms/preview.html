03. WAL Log Framing & AppendEntries

In distributed state machine replication, the Write-Ahead Log (WAL) guarantees persistence before any state transition is applied. In this module, we examine why naive disk writes lead to corrupted consensus records during ungraceful leader power loss.

1. Binary Record Framing

A resilient log format requires length-delimited framing combined with a cyclic redundancy check (CRC32 checksum) to detect partial torn writes:

// Record represents a binary framed entry on disk
type LogRecord struct {
    CRC       uint32 // CRC32-IEEE checksum of Term + Index + Payload
    Term      uint64 // Raft term counter
    Index     uint64 // Monotonic 1-based log index
    DataSize  uint32 // Length of state machine payload
    Data      []byte // Command byte stream
}

2. Idempotent AppendEntries Semantics

Network partitions frequently trigger duplicate RPC deliveries. Followers must verify the (prevLogIndex, prevLogTerm) condition before committing the incoming chunk into their WAL segment.

Why not just use JSON or Protocol Buffers for the WAL entries directly?
Protobuf or JSON serializes structured payloads cleanly, but doesn't handle low-level disk boundaries. If the OS flushes 512 bytes of a 1024-byte protobuf before power cuts out, the decoder will fail with an unrecoverable corrupted stream.

A custom binary frame with a 4-byte CRC header lets your WAL reader discard incomplete tail entries cleanly upon crash recovery!
